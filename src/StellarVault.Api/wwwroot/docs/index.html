StellarVault B2B API v1

Authenticated, tenant-isolated Stellar network discovery and read-only transaction receipt inspection.

OpenAPI specification · Integration and operator guide

Authentication

Send your operator-issued key in Authorization: Bearer <api-key>. Keep keys in a server-side secret manager, never browser bundles or URLs. Only granted network aliases are accessible.

Routes

  • GET /health/live — process health
  • GET /health/ready — configuration readiness
  • GET /v1/capabilities — supported capabilities
  • GET /v1/networks — granted network aliases
  • GET /v1/networks/{network}/transactions/{hash} — successful receipt observation

Errors

400 invalid input; 401 invalid/missing key; 404 unavailable or ungranted network/receipt; 429 rate limit (observe Retry-After); 502 upstream identity/availability failure; 504 inspection deadline.

Evidence boundary

A successful receipt is endpoint-attested, not independent proof of record contents. Responses retain recordLinkedToTransaction=false and mutationConfirmed=false. An unavailable receipt never authorizes resubmission.

This API does not accept signing keys, store customer vault records or submit transactions.
